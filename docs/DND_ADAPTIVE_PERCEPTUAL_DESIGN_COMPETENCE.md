# D-ND Adaptive Perceptual Design Competence

Status: candidate competence derived from the MAIOS/MMK visual studies.

This competence defines how an AI or coding agent may translate context, intent,
state and user preference into a coherent visual surface without turning a design
system into a fixed theme or an artistic collage.

It extends `ADAPTIVE_SEMANTIC_SURFACE.md`. The semantic surface defines the
behavioral and compositional contract. This competence defines how perception is
orchestrated inside that contract.

## One-Sentence Contract

This competence helps a system vary color, density, spacing, emphasis and visual
rhythm while preserving meaning, action boundaries, orientation and user control.

It does not authorize hidden profiling, silent control relocation, decorative
simulation of intelligence or the literal imitation of a painting.

## The D-ND Design Model

D-ND visual design keeps two conditions simultaneously true:

1. **Invariant operational meaning** — action meaning, state, evidence, focus order,
   safety boundaries and orientation remain stable.
2. **Variable perceptual expression** — hue, field balance, density, disclosure,
   rhythm and local composition may adapt to context and user needs.

The included third condition is the adaptive perceptual field: a reversible layer
that translates stable meaning into the most useful current expression.

```text
operational invariant
        +
perceptual variation
        ->
adaptive perceptual field
```

The expression may change. The contract may not disappear.

## What The Visual Studies Establish

The MAIOS/MMK studies produced three useful conclusions.

### 1. A clean light interface is not enough

Open space, cream surfaces and abstract geometry improve legibility, but a generic
SaaS card grid does not communicate D-ND continuity by itself. Equal cards, equal
weights and repeated containers flatten the conceptual hierarchy.

### 2. Rich color is useful only when roles remain legible

Kandinsky-like circles, lines and complementary accents introduce rhythm and
conceptual tension. When every module receives a different vivid hue, however,
color becomes taxonomy, state, decoration and priority at the same time. The user
can no longer tell why an element is prominent.

### 3. The design guide is stronger than the generated page

The most reusable result is not one visual composition. It is a competence that
separates:

- semantic role;
- attention level;
- depth or surface mode;
- relation and proximity;
- state transition.

A page is one execution of this competence, not the competence itself.

## Five Independent Perceptual Channels

Do not ask one color to communicate everything. Encode meaning through five
channels that may reinforce one another.

| Channel | Primary meaning | Typical controls |
| --- | --- | --- |
| Hue family | semantic function or domain | blue coordination, violet knowledge, green verified state |
| Luminance | depth, readability and surface plane | light reading field, dark inspection field |
| Saturation / contrast | attention and activation | muted background, vivid current decision |
| Area / scale | information weight | large focus field, compact metadata block |
| Space / relation | conceptual proximity and possibility | grouping, separation, open margin, overlap |
| Motion | change over time | disclosure, transition, verification, source-to-result movement |

Motion is listed separately because it is temporal. The first five channels must
still communicate the state when motion is disabled.

## Stable Semantic Roles, Variable Palette Recipes

The stable layer names roles, not permanent colors.

Required roles:

- `surface.reading` — prose, orientation and calm work;
- `surface.system` — coordination, structure and operational depth;
- `surface.knowledge` — research, interpretation and cognitive support;
- `surface.attention` — selected possibility or important information;
- `surface.decision` — bounded action with consequence;
- `surface.verified` — confirmed state, success or stable operation;
- `surface.critical` — failure, destructive action or real risk;
- `surface.neutral` — metadata, inactive tools and supporting structure.

A project profile maps these roles to a palette recipe. Different products may use
different hues while preserving the same semantic roles and contrast contract.

### MAIOS/MMK candidate recipe

The current visual studies support this profile:

| Role | Candidate family | Function |
| --- | --- | --- |
| Reading | warm ivory / sand | focus, prose, primary workspace |
| System | deep indigo / midnight blue | MMK, coordination, navigation and system depth |
| Knowledge | violet / periwinkle | research, memory, interpretation and cognitive modules |
| Information | medium blue | data, links, active context and neutral system relations |
| Verified | olive / restrained green | success, stable operation and confirmed state |
| Attention | warm yellow | option, evidence, suggestion and local emphasis |
| Decision | orange / vermilion | primary action, consequence and explicit activation |
| Critical | deep red | destructive, blocked or high-risk state only |
| Neutral | warm cream and graphite | base, text and low-priority structure |

The green is not a generic brand accent over every blue field. It is a scarce state
signal. Blue-green adjacency must be separated by sufficient luminance contrast,
a light boundary, scale difference or another redundant cue.

## Attention Ladder

Priority is not a fixed color. It is the combined result of contrast, saturation,
scale, position and available negative space.

### Level 0 — Ambient

- background and structural rhythm;
- lowest saturation and local contrast;
- no actionable control;
- may contain restrained abstract geometry.

### Level 1 — Supporting

- metadata, labels, passive status and secondary navigation;
- compact size and stable position;
- readable but visually quiet.

### Level 2 — Informative

- cards, related contexts, knowledge and inspectable results;
- moderate contrast;
- may enter through progressive disclosure.

### Level 3 — Active

- current task, selected plane, next safe action and active state;
- stronger contrast, larger area or privileged position;
- only one dominant active focus per region.

### Level 4 — Critical / consequential

- irreversible decision, real risk, failure or required human confirmation;
- strongest justified contrast;
- never used as ordinary brand emphasis;
- must include text and iconography, not color alone.

Rule:

> The stronger the contrast and chromatic intensity, the stronger the functional
> justification must be.

## Negative Space As Information

Negative space is an active component of the model.

Use it to communicate:

- **focus** — a dominant object receives a larger quiet field;
- **relation** — related elements share proximity and alignment;
- **weak relation** — optional or deferred elements remain separated;
- **possibility** — an open margin preserves room for an unresolved next movement;
- **boundary** — a discontinuity marks a change of plane or responsibility;
- **control mode** — spacing compresses only when comparison and inspection are
  required.

Do not fill unused space with decorative cards. Do not hide essential controls by
making absence carry meaning alone. Space must be reinforced by labels, alignment,
color, line or state text.

## Artistic References As Operators

Artistic references are internal design operators. They are not visual costumes.

### Mondrian — macro structure

Use for:

- unequal field proportions;
- stable axes and alignment;
- balance between large calm areas and small high-weight accents;
- selective visible grid lines.

Do not reproduce a Mondrian painting or distribute primary colors uniformly.

### Bauhaus — functional reduction

Use for:

- direct component form;
- legible hierarchy;
- geometry with an explicit function;
- restrained type and icon systems.

### Scandinavian ergonomics — default calm

Use for:

- readable controls;
- comfortable spacing;
- low-friction interaction;
- material warmth without visual noise;
- predictable recovery and focus behavior.

### Modern Japanese print — interval and composition

Use for:

- negative space;
- asymmetric cropping;
- limited local ink sets;
- editorial rhythm;
- a clear relation between image and type.

Do not use untranslated Japanese text or repeated cultural symbols as decoration.

### Kandinsky — relational event

Use for:

- circles, lines, diagonals and scale shifts that express a real relation;
- dynamic diagrams;
- one controlled counterpoint inside a stable grid;
- tension between a central field and an eccentric event.

Do not fill every empty area with abstract geometry.

### Van Gogh / Impressionist color — adjacency and temperature

Use for:

- complementary temperature changes;
- local optical contrast;
- warm and cool fields that distinguish functions;
- color relationships that remain lively without glow effects.

Do not use brush texture, painting fragments or literal scenery as the product UI.
The transferable value is chromatic relation, not the painted surface.

## Component Mapping

### Sidebar and navigation

- use the system/depth surface as a stable anchor when the product requires a
  persistent operating frame;
- active navigation uses position, label weight and one state marker;
- avoid a full vivid fill on every active row;
- local status color is secondary to route orientation.

### Cards

- cards represent discrete records, tools or inspectable states;
- do not assign each card a different hue merely to create variety;
- use a shared base surface and one role accent when possible;
- card prominence must not exceed current task prominence;
- large conceptual groups may remain unboxed.

### Buttons

- ordinary progression: system or neutral role;
- suggestion / option: attention role with dark text;
- verified continuation: verified role;
- consequential action: decision role;
- destructive or blocked action: critical role;
- one primary action per decision field.

### Modals and inspectors

- reading or editing: light reading surface;
- system inspection: dark system surface;
- option comparison: attention surface used locally;
- confirmation with consequence: decision or critical surface;
- verified result: verified accent, not a full green page by default.

### Diagrams

- nodes use semantic roles, not decorative variety;
- line weight and spacing carry relation strength;
- a maximum of five to seven visible nodes before grouping;
- dark and light versions must preserve the same logical hierarchy;
- no animated node may imply live activity without verified state data.

## Surface Composition For A Single Viewport

A desktop surface may behave like a large mobile interface: one coherent viewport,
no required page scrolling for the primary task and secondary systems revealed at
the edges.

Recommended anchors:

1. active context and task;
2. primary work or conversation field;
3. next safe action or verification boundary.

Recommended zones:

- persistent navigation edge;
- broad focus field with generous negative space;
- optional system / MMK inspector field;
- bottom action composer;
- drawers or sheets for specifications, logs and management controls.

A no-scroll viewport is a product-shell option, not a rule for public articles.
Long reading pages should preserve normal document scrolling.

## Adaptive Rules

The system may adapt:

- local density;
- field proportions;
- disclosure depth;
- ordering of non-critical supporting information;
- diagram detail;
- suggestion prominence;
- motion detail;
- local palette recipe within the verified contrast set.

The system may not silently adapt:

- action meaning or wording;
- destructive-action position;
- consent and verification boundaries;
- keyboard order;
- accessibility preferences;
- current-state claims;
- the presence of a required recovery control;
- the user's explicit theme preference.

Every adaptive state must provide:

- a visible reason or contextual cue;
- user override;
- baseline restore;
- persistence rules when appropriate;
- a reduced-motion equivalent.

## Contrast And Accessibility Gate

Before a palette recipe is accepted:

- normal text meets WCAG AA contrast;
- large text and icons are still legible under common color-vision differences;
- state is never color-only;
- light and dark fields use explicit text tokens;
- saturated backgrounds are tested with real body copy, not only large headings;
- focus indicators remain visible on every semantic surface;
- disabled state remains distinguishable without becoming unreadable;
- high-contrast and reduced-motion preferences are respected.

Do not hard-code a contrast ratio from a visual mockup. Calculate and test the final
production color pair.

## Agent Adoption Procedure

Before applying this competence, the coding agent must:

1. inspect the target surface, current state and capability boundaries;
2. identify the three primary anchors;
3. map semantic roles before choosing colors;
4. select or create one project palette recipe;
5. build an attention map for the viewport;
6. remove decorative containers that do not represent an object or boundary;
7. define progressive-disclosure recovery behavior;
8. verify keyboard, mobile, contrast and reduced motion;
9. compare the result with the baseline and document what changed;
10. keep the pattern candidate until it survives a second target surface.

## Promotion Evidence

This competence remains candidate until the repository contains:

- one responsive MAIOS or equivalent implementation;
- one second domain implementation using a different palette recipe;
- automated token or contrast checks;
- keyboard and reduced-motion verification;
- a documented baseline restore path;
- evidence that the same semantic roles survive Paper, Ink and Hybrid modes;
- user or operator review showing improved orientation rather than only visual
  preference.

## Compact Rule

```text
meaning is invariant;
expression may adapt;
color names the role;
contrast names the priority;
space names the relation;
motion names the change;
the user keeps direction.
```
