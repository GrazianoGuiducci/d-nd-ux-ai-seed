# Controlled first exercise — MAIOS launch

Core: D-ND Design Kernel 0.1.0.
Exercise: current receiver, 23 September 2026; not an independent user study.

## Source and selected result

The operator wants the launch to reach people who know conversational AI and
sometimes coding hosts, without requiring prior knowledge of semantic kernels.
Social expression, a light creator contact and a richer linked entry are distinct
jobs. The two existing products may be used separately or together. Products and
production site remain unchanged.

The Design Kernel was formed through Meta_Skill's competence-formation relation,
RepoKernel-native source-preserving synthesis/transfer and the actual design,
writing and business knowledge. No compiler, external agent or new runtime was
invoked merely because those methods participated.

## Three contrasting decisions actually formed

**Email encounter:** make text and one useful destination sufficient when images
are unavailable. Result: a text-first encounter contract, not an embedded picture
or new email draft. Personalisation belongs to the relationship and writing
owners. No email was sent. The stronger claim "nobody knows it yet" was removed
from the design premise: an announcement date does not establish that fact.

**Interactive first entry:** help a person recognise their working surface and
reach the relevant product. Result: `index.html`, an illustrative two-entry
composition with current MAIOS-source colours, editable text, native controls,
a labelled source-continuity diagram and no remote assets. HTML/CSS is sufficient
for this relationship; the present exercise does not establish that 3D is never
useful. The copy is a contextual writing/design candidate, not published copy.

**Dense-workspace contrast:** the repository's existing complete UX units remain
the right starting knowledge for a task needing simultaneous context, work and
detail. Result: no new workspace implementation and no promotion of the landing
as a universal layout. This is a contrasting design decision in the same receiver,
not evidence from a second production deployment.

## Formation and reread changed the method

A proposed app-to-app visual could imply automatic synchronisation. The example
instead locates useful knowledge, its durable source and later access; the
perceptual and spatial methods now preserve this distinction explicitly.

The existing MAIOS CSS supplies a cyan/green/warm-ground relational field. The
old candidate's palette and remembered red/black suggestions were not promoted
by recency of discussion. That distinction now lives in the profile.

The existing package includes all `skills/`, `docs/` and `demo/`. Placing the new
kernel there would silently expand the next npm payload. Core sources therefore
live under `design/`, with root source entries separate from package exports.
The README changes only to make both source roles discoverable.

During browser-test preparation, the test initially resolved the wrong preview
path and attempted file navigation, which the host blocked. The path was fixed;
the test now renders the exact self-contained HTML in memory. This is a test
harness correction, not evidence of a product defect or broader kernel learning.

## What was exercised

The browser exercise covers six widths (320, 375, 768, 1024, 1366, 1920), both
entry states, horizontal overflow, content/selection alignment, separate desktop
fields, keyboard selection, focus preservation, resize continuity, native
keyboard disclosure, reduced motion, forced-colour selection, no-JavaScript
entries, no external asset requests and seven opaque text-colour pairs.

The final controlled run returned **64/64 checks passed** in Chromium
144.0.7559.96. The exact HTML was rendered with Playwright `set_content` because
the file-navigation path was unavailable in this host. There are no relative
resources. This does not test public hosting or a deployed site's delivery.

Source-integrity checks separately cover the new local entries, manifest,
metadata, profile isolation and the package-boundary observation. Neither the
mechanical checks nor the author's visual inspection prove receiver understanding,
semantic-kernel performance or durable cross-host assimilation.

Replay, with an already installed Playwright/Chromium:

```bash
python design/tests/verify_preview.py --output /tmp/design-preview-proof
python -m unittest discover -s design/tests -p 'test_*.py' -v
```

The verifier installs nothing. Exact file identities and scope are recorded in
`VERIFICATION.json`. The HTML remains a source exercise, not a new public route.

## Remaining distinctions

Not performed: full Agentic UX Seed build/test, installed Codex adapter test,
independent first-encounter test, image/video generation, public deployment,
product installation, email/social effects, T0 measurement or global owner wiring.
The temporary container could not clone GitHub by network; source was read through
the connected repository tools and the bounded new files were constructed locally.
Do not report this partial checkout as a complete library test environment.

## Return

Perceptual/spatial methods learned the source-vs-app-bridge distinction; the
project profile learned how to resolve old and current brand evidence; the kernel
entry learned to separate a source-domain kernel from a co-located npm package.
The integration map identifies external owner changes but does not perform them.

The next useful work is either exact owner wiring or a selected final launch
artifact. It is not another general census, another invented style taxonomy or
an additional proof requirement on the already closed products.
