# Contextual reading continuity

Formed 2026-10-06 by ChatGPT through Kernel Nautico CVS-01. Owner: Interaction Quality, D-ND Design Kernel. This is a source-method return, not an npm release or proof of production adoption.

## Preserve reference without inventing identity

A person can follow one question across representations that contain different objects. Preserve the functional subject or inquiry when material, but keep its representatives distinct: requirement, drawing revision, alternative, component and observed installation need not share an identity.

Before mapping selection into a new representation, distinguish:

- the same object shown differently;
- a different object connected through an explicit source-owned relation;
- a correspondence which is not established;
- a selected object not represented in the receiving view.

Do not silently substitute an available node when the selected object is missing. Keep the selection recoverable, describe the absence and expose a meaningful return or related view. Do not let visual continuity promote a proposal into an installed or approved state. A shared label or product silhouette cannot establish equivalence.

The Nautico prototype keeps an access question separate from project A, variant B, component B and the unknown onboard configuration. A supply-network selection can continue into a construction or service view without inheriting an installation claim. This is a product-specific exercise of the reusable representation relation, not a universal requirement for a new identity layer in every UI.

## Reading state is not work state

A view, selection, comparison and reading history can live in a local controller without duplicating the case owner. A reading bookmark does not replace a project archive. Binding a bookmark to a known representation version can prevent an old selection from being silently interpreted in a different field; use the smallest contract that the actual product needs.

A user's private question may remain in the local reading context without entering an exported bookmark or public conversation context. If a wider handoff is selected, show its exact content and destination. Public labels and a public draft are not authority to include private source records.

## Perceivable completion under reflow

Updating a detail region outside the viewport is not enough to make the consequence of selection perceivable. On a single-pane receiver, deliberately connect selection, viewport, focus and return. A details-first transition may preserve the selected control as the return destination. On a wide receiver where the detail is already visible, keep focus at the selected control when that better preserves orientation.

Test the actual transition and its reverse. Do not infer usability from an unoverflowed final screenshot. If changing representation or resizing removes the original control, return to the corresponding control of the same object or a named stable context, not silently to the document body.

## Host composition

When the existing product owns context, its observation remains authoritative. Route outgoing context changes through that owner and qualify the observed result before the dependent reading view commits. Incoming manual changes use the same observation path. A requested target and an unexpected observed target remain different facts; do not report success for the former because the latter exists.

The exact mechanism can remain synchronous. Do not duplicate an asynchronous bridge or invent a global coordinator for a local controller. The same rule covers composer integration: a dispatched draft is not yet an observed draft, and a visible draft is not a sent message.
