# Relational Chromatic Design And Evolution

Use this reference when designing or reviewing a proprietary chromatic system,
an adaptive visual field, or a project whose identity must not be organized as
light, dark or hybrid themes.

## Scope And Invariant

Apply this method only after the target project selects a relational chromatic
field. Do not impose it on a product that genuinely requires user-selectable
appearance themes.

Preserve this invariant:

```text
one recognizable chromatic substrate
+ independent local vectors
+ stable semantic meaning and authority
-> one evolving visual field
```

Use local value changes for readability and depth. Do not let those changes
become alternate page identities.

## Artifact Separation

Classify the artifact before evaluating its appearance:

```text
calibration_lab:
  isolates variables, exposes controls, records observations and may use
  technical language.

product_surface:
  starts from the user's durable job, current object and available action.

public_surface:
  starts from verified project meaning and navigation; hides internal design,
  gate and receipt vocabulary unless it changes the visitor's decision.
```

Never copy the Lab composition, control density or technical labels into a
target by visual resemblance. Carry the behavior contract and rebuild the
composition around the real content.

## Design Gate

Before changing color or composition, fill:

```text
target_surface:
artifact_class:
durable_job_or_public_meaning:
primary_object:
current_action:
stable_semantic_roles:
selected_substrate:
active_view_states:
adaptive_vectors:
authority_and_reality_boundary:
mobile_primary_order:
validation:
project_specific_elements_not_to_generalize:
```

Review in this order:

```text
meaning and truthful state
-> behavior of each view state
-> hierarchy and attention
-> spatial composition and negative space
-> chromatic-vector discrimination
-> typography and language
-> responsive order
-> accessibility and recovery
-> proprietary identity
```

Do not repair a hierarchy or behavior failure by adding more colors.

## View-State Behavior

A named state is valid only when it changes the information architecture or
interaction plane in an observable and reversible way.

```text
focus:
  one dominant object and one next action;
  expanded negative space;
  secondary controls latent;
  inspector closed unless required by the task.

relations:
  related objects and labelled connections become visible;
  each object retains its semantic identity;
  unrelated detail recedes without disappearing from navigation.

control:
  density increases;
  evidence, parameters, boundaries and recovery become inspectable;
  the primary object remains identifiable.
```

Preserve relational continuity across those states. When a relation is selected
in `relations`, `control` must keep the selected object and its path visibly
traceable unless the user explicitly cancels the selection. An inspector that
replaces the path with unrelated detail breaks continuity even when its content
is correct.

Reject a state implementation when only a line, background effect, accent or
animation changes while hierarchy, density and disclosure remain unchanged.

## Chromatic-Vector Discipline

Keep the vectors independent and perceptually distinguishable:

| Vector | Carry | Must not collapse into |
| --- | --- | --- |
| Semantic role | function and responsibility | decorative variety or global brand accent |
| Temperature | relation and adjacency | success, danger or page mode |
| Local depth | inspection distance and structural condensation | dark theme or authority |
| Chromatic pressure | attention, weight and consequence | role identity |
| Certainty | evidence through edge definition, opacity and state text | hidden confidence claim |
| Boundary | ownership, interruption and consequence | decoration |

Require one-channel trials while calibrating. Reset non-selected vectors to a
known baseline and state that behavior clearly. Later, test composed states
separately; isolation proves discrimination but not orchestration.

For related semantic objects, bind each marker to its own role token. Never
paint every related marker with the currently selected role.

Scope an adaptive vector to the semantic object or region that owns its
meaning. Changing a root or page-level field is valid only when the meaning is
truly global; otherwise it creates theme-like bleed and destroys local
discrimination.

Test the final rendered combinations. Raw-token contrast values do not prove
contrast after gradients, transparency, `color-mix`, blur or overlays.

Do not make one semantic hue carry expression, text legibility and graphical
separation by itself. Use a paired contract:

```text
surface -> the rendered membrane or field region;
on-surface -> ordinary text and controls on that surface;
role -> expressive fill, resonance or local pressure;
role-strong -> semantic text, relation path, border or state marker.
```

Normal text must reach at least 4.5:1 and meaningful non-text graphics 3:1 in
the final rendered context. Do not lower text opacity to create hierarchy when
that makes the effective pair fail. Typography, spacing and weight can make
secondary text quieter without weakening legibility.

## Hierarchy And Composition

Expose no more than three stable anchors in one viewport:

1. active context or meaning;
2. primary object or task;
3. next action, consequence or verification state.

Reduce equal-weight controls, labels and panels. Keep an inspector latent in
focus state and available in control state. Remove nested panels when spacing,
alignment or one structural edge can express the same relation.

Use a living grid through unequal proportions, shared baselines and selective
visible axes. Preserve at least one large unboxed region. Treat geometry as a
relation carrier:

```text
line -> named connection or transition;
circle/node -> identifiable object or state;
break -> boundary or change of owner;
open interval -> unresolved possibility;
overlap -> verified convergence or dependency.
```

Remove any shape whose meaning cannot be explained in one sentence.

In responsive product proofs, bind relation geometry to the rendered bounds of
the objects it connects, or use a layout that guarantees the endpoints. Fixed
illustration coordinates are not evidence that a relation survives reflow.
Provide a labelled linear equivalent when spatial position or paths carry
meaning; hiding the diagram must not hide the relation.

Preserve responsive semantic parity without forcing geometric parity. When the
spatial field no longer lets the primary reading object and relation ensemble be
understood in one compact frame, switch composition rather than shrinking the
desktop graph. A validated mobile form is:

```text
orientation
-> active reading object
-> ordered relation deck with explicit selected state
-> compact continuity receipt
-> sequential inspector as the final focus owner
```

Hide decorative connection paths in this form; the cards and named predicates
carry the relation. Keep the same data, selection state, accessible names,
focus-return contract and linear equivalent. Treat a separate mobile page or
duplicated state machine as a last resort, because it invites semantic drift.

Treat a relational view change as one coordinated topology transition:

The state contract is atomic. Keep tab, state name, orientation copy and reading
content on the origin together during departure; commit all four to the
destination together. Never expose a frame where the new tab is active while
the previous reading card has returned or remains visible.

```text
source ensemble becomes visible and settles
-> selected source names its predicate and destination
-> paths draw from sources toward the destination's semantic hub or ports
-> reading surface repositions while endpoints update every frame
-> selected mother surface remains visible or returns in a measured final slot
-> stable destination, ready receipt and focus transfer
```

Do not calculate paths only before and after a CSS layout transition. That
makes lines converge on stale geometry and then snap to the card. Do not attach
relations to multiple ports merely to distinguish their colors. If they feed
one reading object, converge them on one stable hub; reserve separate ports for
separate destination functions. Once the paths are mounted, changing selection
must preserve their geometry and dash state while opacity and weight migrate to
the active connection. The destination may adopt the selected relation's
measured pastel membrane, while body text continues to use the declared
on-surface ink and a textual `source -> predicate -> object` statement carries
the same meaning without motion.

The reading card still needs a legible change when selection moves. Transition
its inner plane without disturbing topology: old content leaves, the semantic
swap occurs while hidden, card height interpolates, then new content enters.
Keep the hub fixed and avoid scale. A return from a dependent inspector is not
another topology reveal: restore the previously mounted relation scene with one
reverse layout movement and retain every path's dash state. If a linear or
alternative disclosure recenters the viewport, its expansion and viewport
movement share duration and easing and complete before focus transfers.

Do not give a relation and a dependent view the same label unless they truly are
the same function. Name the relation by what it contributes (`Criteri`) and the
view by what the user does there (`Verifica`). When entering that view, close
the relation ensemble before the inspector changes width. Preserve the selected
source/path visibly only if its coordinate space stays stable. When the parent
is resizing, hide the selected raccord, let the destination settle, measure a
final slot between the reading surface and inspector with explicit edge gaps,
then reveal it there. A delayed final-position reveal is preferable to a
three-stage jump, and percentage coordinates must not carry an element through
a resizing parent.

The field and dependent inspector are one coupled surface transition. Animate
their shared track through compatible value types and verify rendered width on
successive frames; a declared transition that holds and then jumps is a failed
motion contract. The inspector shell may enter with the first field-width
change. When the inspector is the final focus owner, settle the reading surface
and selected mother raccord together before inspector orientation and evidence
appear. The last semantic reveal must be the surface that receives focus.
Closing reverses the same geometry with the inspector inert until hide and
focus restoration complete.

A bounded desktop inspector should not need its own scrollbar merely because
spacing and width are fixed. Adapt width and internal vertical rhythm to the
available width and height and verify the final required component lies inside
the panel. At the failure threshold, stack it with natural page height instead
of hiding overflow or compressing text below readable size.

Place sources in an ordered, inspectable spatial circuit and reserve separate
zones for the reading object, connection hub and status receipt. The receipt is
structured as state, relation and consequence rather than a repeated sentence.
Verify zero card/node/receipt intersections at target widths. When an inspector
would make either column unreadably narrow, stack it as the next viewport section
and frame that section. Closing a linear alternative restores the current
semantic owner (reading object or inspector), not automatically its summary.

## Typography And Language

Use display typography for short declarations, an open text face for reading
and controls, and monospace only for evidence or machine-readable state.

Keep ordinary labels comfortably readable. Do not rely on 10-11 px uppercase
monospace text for navigation, explanations or state. Keep one language per
surface unless the product explicitly presents a bilingual comparison.

Use project language on product and public surfaces. Keep names such as field,
vector, synthetic fixture, baseline and receipt inside the Lab or a selected
technical explanation.

## Responsive And Accessibility Checks

On narrow screens, show the primary object and its result before calibration
controls. Move advanced controls into a recoverable sheet or disclosure.

Verify:

- 375, 768, 1024, 1366 px and wide desktop;
- no horizontal overflow or accidental one-word title stacks;
- touch targets of at least 44 px where practical;
- visible focus on every mixed field;
- focus entry and return for inspectors and drawers;
- `Escape`, `aria-controls` and `aria-expanded` for temporary disclosure;
- visually latent or hidden objects removed from the tab order and accessibility
  tree, not only faded or stripped of pointer events;
- reduced-motion and forced-colors behavior;
- final computed contrast across every supported vector combination;
- meaning available without color, motion or spatial layout alone.
- returning to Focus clears prior local chromatic pressure unless the retained
  relation remains explicitly named and visible;
- confirmation exposes stable confirm/revoke state instead of counting clicks;
- native controls inherit an intentional local scheme; do not declare a global
  light or dark scheme merely to normalize their default appearance.

## Project-Profile Boundary

Keep the reusable method here. Keep these in the selected project profile:

- substrate and exact palette;
- typography files and licensing;
- product vocabulary and public copy;
- project-specific semantic roles;
- diagrams tied to real project objects;
- maturity and publication state.

For MAIOS, use the adaptive-semantic-surface candidate and the MAIOS site
communication gate. Treat the mineral field as candidate project evidence,
not as a universal D-ND palette. Do not mutate `maios_it` from the Lab or from
this reference alone.

## Evolution Loop And Receipt

Improve the competence from observed work, not aesthetic preference alone:

```text
apply the current method to one bounded artifact
-> compare behavior and hierarchy with the baseline
-> record the operator correction or observed failure
-> separate project fact from reusable invariant
-> patch the smallest owning Skill or reference
-> validate the Skill
-> forward-test substantial changes when safe
-> queue wider Seed, THIA or TMx propagation for a separate transfer gate
```

Preserve only a reusable delta with:

```text
origin_surface:
observed_problem:
operator_correction:
reusable_invariant:
project_specific_residue:
changed_skill_or_reference:
validation:
not_yet_proved:
next_bounded_test:
```

Current integrated learning from the first MAIOS Chromatic Field Lab:

- a correct single-field theory can still produce a generic technical panel;
- view-state names are insufficient unless composition and disclosure change;
- a calibration control rail must not outrank the object being calibrated;
- related roles must retain their own colors instead of inheriting the current
  selection;
- repeated nested rectangles weaken the perception of one continuous field;
- on mobile, the visible result must precede the complete control apparatus;
- a proprietary identity emerges from repeatable relational grammar, not from
  a larger palette or decorative abstraction.
- expressive role colors need separate strong companions for readable labels,
  paths and markers;
- a Focus label is not a reset if the previous relation still colors the field;
- a spatial relation needs a recoverable linear reading;
- text transparency can silently invalidate an otherwise correct token pair.
- a relational field must become readable as an ensemble before motion selects
  one route and transfers attention;
- path geometry must stay attached throughout a moving layout, not merely at
  its initial and final coordinates;
- attachment topology follows destination meaning: one reading object uses one
  stable convergence hub, while distinct destination functions may use ports;
- selection changes preserve mounted paths and move only active-connection
  emphasis instead of replaying the topology;
- mounted reading content changes through hidden swap and height interpolation;
- dependent-state close restores the prior scene without replaying its entry;
- disclosure expansion and viewport framing settle as one focus movement;
- a selected mother relation can continue into the reading membrane without
  forcing the role hue to carry body-text contrast.

Treat these as working invariants. Revisit them when a second real project
surface supplies contrary evidence.
