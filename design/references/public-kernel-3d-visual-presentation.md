## Operator determination

Every new public kernel will have its own **3D Visual Animation**.

The animation is part of the public presentation architecture of the kernel. It
is not merely decorative launch media.

Its job is to make perceptible:

- how the kernel is used;
- the processes or fields it participates in;
- important state / lifecycle / evolutionary transitions;
- the relationship between experience and later capability;
- larger possibilities opened by the kernel;
- different forms of value for investors, prospective clients and partners.

It acts as both:

~~~text
media presentation
+ cognitive guide
~~~

## Reusable design relation

The cross-kernel function is:

~~~text
kernel truth / identity
+ real operating relations
+ current / direction / horizon distinction
+ receiving situation
-> kernel-native 3D visual system
-> use / process / change / consequence / value become perceptible
-> receiver can form a usable mental model
-> deeper source / technical / business surfaces remain reachable
~~~

The output family can include:

~~~text
hero / master animation
collaboration cut
investor cut
deck keyframes
one-page visual
site / interactive derivative
social derivatives
~~~

These are projections from one source-bound visual system, not independent
stories.

## What is shared across public kernels

The following relations are candidates for cross-kernel reuse:

### Presentation function

A public kernel should be explainable through an audiovisual/spatial encounter
that reduces the reconstruction burden on a receiver.

### Cognitive guide function

The visual sequence should help the receiver understand causal relations,
boundaries, state changes and what changes next. It is not only attention media.

### Evolution visibility

When a kernel's value depends on learning, competence, reentry, consequence or
another temporal relation, the animation should make the change visible rather
than merely label it.

### Value plurality

The visual system can distinguish several kinds of value without collapsing
them into a generic benefit claim:

~~~text
understanding
operating participation
continuity
competence
integration
lifecycle
stewardship
strategic possibility
economic / collaboration
~~~

Only value relations supported by the selected kernel and receiver enter an
artifact.

### Artifact family

One master visual grammar should be reusable across presentation surfaces where
that reuse preserves meaning.

## What is not shared by default

Do not turn the first pilot into a universal template.

A future public kernel does not automatically inherit:

- a yacht or physical-product metaphor;
- exploded mechanical assembly;
- FORM / BUILD / LIVE / RETURN;
- technical-dossier aesthetics;
- warm porcelain / bronze materials;
- a specific camera path;
- a 60–90 second runtime;
- Kernel Nautico's lifecycle semantics.

Each kernel forms its own visual morphology from its real object and field.

~~~text
same cross-kernel presentation function
+ different kernel truth / process / receiver
-> different visual grammar
~~~

## 3D production boundary

The operator has selected a 3D visual animation **product/presentation
requirement** for public kernels.

That does not yet prove a distinct industrial-3D competence.

Practical production may require:

- geometry / asset preparation;
- CAD or concept-model translation;
- scene graph architecture;
- materials and lighting;
- camera choreography;
- assembled/exploded transformations;
- procedural state animation;
- technical overlays;
- Blender / Unreal / Three.js / another renderer;
- render, realtime and export pipelines.

Let the first real execution expose what is reusable and what is tool-specific.

Do not create a new competence before the experience produces a residual method
that existing Design owners cannot coherently carry.
