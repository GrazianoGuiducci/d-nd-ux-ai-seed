# Interaction Quality

Version: 0.1.0 · Semantic owner: D-ND Design Kernel / this method.

## Understand the action before the component

Determine what the person is doing, what state is real, what they can change and
what must remain understandable after that change. A public reading page, a
bounded form, a decision surface and a persistent workspace can share visual
primitives without sharing a layout or state machine.

When adopting the existing library, use the public adoption skill and repository
selection skill from the same source revision, then the selected registry item,
behaviour contract, component/template and relevant demo. A missing file is not
satisfied by a similarly named older document. Do not substitute the present
method for a complete component's tested contract.

Choose a workspace shell when context, active work and consequence need to stay
visible. Do not apply it to a landing merely because it is the richest available
component. When no existing component fits, form the smallest useful behaviour
without claiming it already has the library's promotion evidence.

## Preserve agency in the state model

Selection, confirmation, execution and publication are different meanings.
Selecting a card does not silently authorise a consequential action. Keep one
recognisable primary decision in the active reading frame when a decision is
required; do not apply a fixed card quota to a recognition field or catalogue.

An adaptive presentation may change vocabulary, density, examples or disclosure
when useful, but must not silently change action meaning, consent, privacy,
destructive controls or the user's explicit preferences. Contextual suggestions
need an intelligible reason and a correction path when that reason is not obvious.

Derive a displayed result from an identified input state. When that input changes,
invalidate or recompute dependent previews rather than leaving a success marker
attached to a different configuration. Keep selected objects across harmless
resize/reflow or panel changes. Report unavailable capabilities rather than
simulating a successful operation.

## Orientation, focus and recovery

Opening a temporary surface retains its invoking control and the selected
object. Focus enters the meaningful destination and returns to the owner on
close. Hidden or inactive content must not remain reachable in the keyboard or
accessibility tree merely because it is visually transparent.

Match keyboard focus to the final semantic reading plane. A view change commits
its active navigation, label and content together; do not expose a hybrid frame
with the new tab and old content. If space is insufficient, move a dependent
inspector into normal flow instead of hiding essential controls or compressing
text below useful reading size.

Prefer native controls and semantic HTML for the task. Disclosures require a
clear state and recovery; a real modal needs focus containment and restoration.
Do not build a modal for inspection when an ordinary region can preserve context.
Errors belong beside the owning decision and retain its inputs. Stop, retry,
back and recovery must name their actual effects.

## Responsive meaning, not geometric shrinking

Inspect both width and height. Preserve a readable primary object and action,
then make depth available without competing. When a graph no longer fits, a
labelled linear relation deck can preserve meaning better than a smaller graph.
Keep one state source rather than maintaining divergent desktop/mobile truths.

If a spatial connection remains essential, bind its geometry to rendered object
bounds and keep it attached during transitions, not just at their endpoints.
Overlay panels are occluders: calculate usable space rather than hiding the
active object beneath an attractive inspector.

The existing library names 375, 768, 1024, 1366 and wide-desktop checks. Treat those
as useful initial coverage, not proof about all devices. Add the actual failure
threshold, zoom, long text or orientation that can change this implementation.

## Motion and access

Motion explains a transition; it is not a loading claim or artificial urgency.
Pause or reduce optional continuous movement. Respect reduced-motion while
preserving state and meaning; forced colours must still expose controls and
selection. Canvas/WebGL cannot be the only way to reach content or take action.

Do not lower text opacity merely to make a hierarchy quiet. Test the rendered
foreground/background combination, including compositing, not just a colour
swatch. Distinguish text legibility, graphical separation and expressive fill.
Use more than colour for state. The inherited contrast targets are 4.5:1 for
normal text and 3:1 for meaningful non-text graphics; calculate what the final
surface actually displays before claiming compliance.

A first-frame full-viewport composition can be a useful product choice. It is not
a prohibition on scrolling articles or on accessible reflow. Under constrained
space, prefer continued access to content over preserving the poster geometry.

## Quality follows the selected effect

Before claiming implementation success, exercise the changed behaviours:
keyboard access, focus/return, resize, selected-state continuity, errors,
reduced-motion, asset failure and recovery where relevant. A screenshot alone
cannot prove them. A test pass is tied to the exact files, environment and
observations; unchanged neighbouring products do not inherit that proof.

A rendered schematic can validate the prototype's layout and controls without
proving product installation, cross-session continuity or user understanding.
State that distinction in the exercise, not as an unavoidable banner on every
future public product.

## Evolve where the behaviour belongs

A reusable interaction correction returns here or to the existing component
owner when that component caused it. Seed promotion still requires its native
contract and evidence; this kernel does not silently mark a new pattern promoted.
Project-specific colours/copy remain in profiles. If the route failed to read an
already correct contract, repair routing instead of repeating that rule across
several skills.

Controlled launch exercise: a mode selector can change explanatory content
without moving focus away from the selected control. A separate "continue"
action that opens a destination owns a different focus transition. Do not apply
one focus recipe to both just because each is a click.
