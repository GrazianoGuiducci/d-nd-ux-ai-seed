# Source-Grounded Infographic

Version: 0.3.0 · Semantic owner: D-ND Design Kernel / this method.

## Spatial explanation

The object is the relationship that becomes understandable when its elements
can be seen together. A source owner supplies what is true; the writing owner
supplies consequential wording; Perceptual Composition supplies art direction
and the selected project profile. This method forms the spatial grammar.

Begin with subject, real context and a visual question. "Explain the kernel"
is not yet a visual question. "Show what belongs to the project and what belongs
to the tool accessing it" can be one. A source can disclose a better question
while the map is forming; do not protect the first layout from that discovery.

## From relation to geometry

Identify the minimum materially participating objects and the actual predicates
between them. Determine whether the useful view is a comparison, causal map,
role map, field, process landscape, source lineage or another form. A topology
is chosen for the relation, not inherited from a generic network template.

Make relation types legible. Containment, access, sequence, dependency,
comparison and shared origin are not interchangeable edges. A line must not
silently turn "can be used together" into "synchronises automatically". A central
node must not invent a central authority. A before/after view needs an actual
changed condition, not a manufactured failure attributed to another tool.

Use scale, position, negative space, alignment and edge treatment intentionally.
Do not use a decorative biology or orbital metaphor as evidence of scientific
identity. Label a metaphor when its status changes interpretation; remove it
when the label costs more than the form contributes.

## Deep meaning, simple projection

A visual explanation can become simpler only after the source relation is
understood deeply enough to know what can be left latent.

```text
source depth
+ receiver situation
+ materially participating relations
-> semantic awareness of the object
-> select the relation that must be simultaneously perceivable
-> spatial contraction
-> simple map / diagram / image without semantic flattening
```

Do not start from a desired node count, a social-template geometry or the rule
that every graphic needs one CTA. Those can be useful implementation
constraints, but they do not decide which objects or predicates belong in the
visual field.

The visible artifact may carry one relation while the competence retains a
larger source-bound map. That retained depth is not an excuse for ambiguity:
subject, relation type and materially important boundary must remain recoverable
from the artifact itself. Companion text can add context or depth; it should not
repair a missing subject or an invented visual mechanism.

When a later source, consequence or operator correction deepens the meaning,
re-form the visual question before polishing the old geometry. A successful
previous composition is evidence for that earlier field, not authority to keep
the same syntax after the semantic object has changed.


## Consequential synthesis

For the MAIOS campaign, the large infographic owns the **consequential
synthesis** function: it recomposes relations that may have appeared separately
as pills and makes their combined process or system consequence visible.

```text
condition / source
-> transformation
-> intermediate relation(s)
-> changed capability / state / possibility
-> next consequence
```

Do not make a summary by placing several pill cards side by side. The synthesis
must expose what becomes understandable only when the relations are seen
together: dependency, feedback, progression, tension, ownership, branching or
another typed relation.

The infographic can be the first encounter for a reader whose domain already
supports greater complexity. Complexity is not failure when the structure
reduces reconstruction and the reading path remains legible.

When target/domain knowledge changes the useful system question, form a
different consequential view from the same source nucleus rather than merely
changing labels.


## Density and progressive depth

Expose enough to answer the visual question without recreating a whole article
inside the image. There is no universal maximum node count. Group or disclose
when additional simultaneous detail stops helping the selected receiver.

A complete inventory can remain searchable or linked while the visible field
shows the relevant neighbourhood. Keeping some depth latent is not permission
to omit a relationship essential to the current interpretation.

On mobile, preserve semantic parity rather than shrink the desktop graph.
A labelled ordered set can replace connector geometry. Keep the same object,
selection and predicates. Essential information cannot disappear with decorative
lines, hover states, colour, animation or canvas support.

## Produce a usable design result

Supply the visual thesis, relevant source binding, typed objects/relations,
composition, exact label needs, static/linear reading, volatile facts to localise
and exclusions. Include editable vector or DOM text when correctness matters.
A renderer may be SVG, HTML/CSS, image generation, slide software or another
available mechanism; the method is not identified with one renderer.

Cross-surface derivatives preserve the thesis, not the crop alone. A social
image may reveal one relation; the landing can disclose its sources; a product
card can show the relevant entry. Coordinate with the package owner rather
than forcing every derivative to contain the same diagram.

## Readback and continuing method

Inspect final rendering for invented containment, false arrows, unsupported
status, collisions, tiny labels and order changed by reflow. Separate a static
clarity inspection from a real receiver's understanding and from product proof.

Correct a misleading spatial grammar here; return wording to the writing owner,
source error to the object owner and component behaviour to the UX owner.
When another receiver understands the same map differently, preserve both
observations and their contexts rather than averaging them into one verdict.

This source generalises the earlier launch-native infographic faculty. The
original source and its evidence remain preserved. Updating that older entry or
migrating its consumers is a separate integration operation, not something a
new file proves has happened.
