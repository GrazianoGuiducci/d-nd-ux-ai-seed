# Design exchange, without a required workflow

Use this contract when a boundary between owners or receivers needs explicit
state. Do not require a form when the conversation already supplies the relation.
The kernel accepts directly expressed intent and can help form what is missing.

A useful request identifies **what must become understandable or doable, for whom,
on which surface, from which source**. Add a brand profile, exact copy, product
entry, wave/timing, tools, constraints or an effect boundary only when material.

```text
request_ref / source_ref
artifact_job + receiving_context
surface + optional campaign/wave relation
available product/action and its truth owner
writing owner / supplied copy
brand/profile when selected
actual means and current effect ceiling
```

The result carries the formed perceptual relation, medium and composition;
editable copy/asset needs; interaction and access behaviour where relevant;
source/reality boundary; execution/delivery owner and a meaningful observation.
A reference to an existing result is preferable to copying its full profile.

```text
result_ref + request_ref
perceptual thesis / chosen form / reasons
artifact or executor brief
copy and visual relation; accessible/static equivalent when needed
source identity + relevant profile + evidence scope
remaining effect or capability boundary
reusable learning and its owner, only when there is a difference
```

These are semantic coordinates, not a closed JSON schema or a compulsory list.
A file identity can be a path plus content digest when a test or transfer needs
it. No new global registry, event bus or service envelope is installed by this
contract.

## Typical composition

Business/Launch can identify a need such as an understandable public entry for
an announcement. The writing owner and Design Kernel then co-form the artifact.
The medium can change the length of the copy, while a source distinction can
change the visual hierarchy. This is not an assembly line where Design receives
unchangeable words at the end.

A source/product owner can call the kernel without Business. A writing owner can
request spatial explanation. A real receiver's confusion can reopen only the
misleading part. A downstream publication owner decides the exact public effect;
preparing an asset does not perform it.

## Missing access or tools

If an optional domain owner is inaccessible, distinguish known intent/supplied
copy from what still needs that owner. Do not invent current product facts or
claim to have loaded a private skill. Source-independent design work can proceed;
only the dependent assertion or effect remains unresolved.

If a renderer is unavailable, preserve a tool-neutral brief or use another
available renderer that carries the same relation. Do not create an external
service or a paid job without its own selection and authority.

## Learning return

Visual hierarchy/medium -> Perceptual Composition.
Spatial predicates -> Source-Grounded Infographic.
Temporal representation -> Source-Grounded Storyboard.
Interaction/state/recovery -> Interaction Quality or the actual component owner.
Brand-specific decisions -> selected profile.
Words/argument -> writing owner.
Product mechanism -> product owner.
Channel/wave result -> distribution owner.
Formation defect -> kernel entry or generative method that caused it.

Only the changing relation travels. A new owner profile does not overwrite a
receiver's local adaptations, and pointer alignment alone does not prove use.
