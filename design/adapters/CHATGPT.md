# ChatGPT receiver

Use the canonical repository source through the connected tools actually exposed
in this turn. Start at `DESIGN_KERNEL.md` for a new design-domain movement or at
the already known faculty for a continuing one. Reach `design/state/CURRENT.md`
only when current source state matters.

The methods are exercised in the current conversation. Their presence does not
create a persistent agent, automatic trigger, background design task, filesystem
on another node, or a callable tool from a sibling's registry.

Image generation, document/vector construction, a temporary local browser or
repository tools can execute selected parts if available. Observe the actual
artifact. Do not claim rendering or host installation from a source read.

## Imported visuals intended for public reuse

When a request brings a visual or deck generated elsewhere into public reuse, reach [Perceptual Composition](../skills/perceptual-composition/SKILL.md) and [Source-Grounded Infographic](../skills/source-grounded-infographic/SKILL.md) before transforming or exporting it. Apply their existing source, profile and evidence-plane methods; the imported artifact records a previous transformation, not authority for every displayed relation.

Read the actual rendering, including attribution-bearing elements beyond the main copy: footers, named components, axes, labels, QR codes, links, dates and event metadata. Preserve the received artifact while rebinding the relations selected for reuse. When a comparison, connector or label changes whose result appears, what a source supports or which capability exists, return that difference to the source or artifact-family owner. Design corrects expression without promoting an imported claim into product truth. Keep exact action destinations controllable and apply the existing readback before closure.

## Competence preparation is not image production

When the operator asks to **catalogue visual principles, prepare the brand coding, find design competences or study supplied examples**, those images are evidence for competence formation. A future intention to generate image families is not itself selection of an image to render in this turn. First reach the real Design Kernel, the project profile, and any current editorial/product owner. Preserve the selected formation in its owner.

The 31 October MAIOS case exposed this receiver error: an image was generated as a supposed “visual code” while the operator had selected reading and evolving the design competence. The canonical method was already present; correct the receiver's **task-intent interpretation and source entry** rather than creating a rival image skill. The MAIOS-specific candidate is at [VISUAL_CONTENT_GRAMMAR](../profiles/maios/VISUAL_CONTENT_GRAMMAR.md). Generation becomes appropriate after a concrete artifact is selected and its content/receiving conditions are understood.

## Image-generation execution path

### Source-to-prompt participation — actual MPK cover failure, 31 October 2026

The MAIOS *Usare MAIOS Project Kernel* cover exercise exposed a **second, different receiver failure** after the earlier premature infographic: Design/Editoriali and the MAIOS Visual Content Grammar had been read and evolved; the selected thesis was a spacious editorial cover expressing one shared project/work field and the kernel's meaningful continuing method. Yet the actual ImageGen instruction introduced a stock seated professional at a laptop, glowing holographic MPK dashboard and a bottom linear four-icon chain (Context → Competences → Work → Learning). The rendered cover followed those instructions. The primary divergence occurred **when the assistant formed the executor prompt**, not because the image generator disregarded a correct design brief.

Carry the meaning into the actual generative instruction at the point it forms. Recognize if an inherited familiar image or layout is replacing a selected source relation: a figure at a laptop, neon dashboard, central-node diagram, icon chain, four-card summary or scenic motif is one possible expression only when the **specific chosen visual thesis** warrants it. Let source object, visual relation and intended reading experience determine the scene, and leave the renderer freedom inside that determined field. Aesthetic words and brand color tokens alone do not preserve the source.

For the selected MPK cover, the source's **interacting relations and their useful continuation** are the content; the previous explanatory diagrams belong to the PDF. A conceptual project-field composition may depict action and transformation without manufacturing a numbered pipeline. For another artifact (social post, profile header, industrial product), re-form scene and content from its own current audience, job, product state and brand profile; do not export this one cover's sparsity as a universal law. This is an in-flow source/prompt correction, not a new approval stage, fixed prompt template or extra skill.

The immediately generated candidate was visible in the conversation; its visual interpretation is evidence of the failure, not acceptance, GitHub asset publication, or proof that the corrected method will be used in the next non-identical case. A later real prompt and rendering must demonstrate the difference.

For an image-generation or image-edit movement, do not move directly from the
operator's prose to a generic aesthetic prompt. Resolve the active design method
and, when a real project or brand exists, bring its current project profile and
the strongest available visual source evidence into the generation brief before
invoking a renderer. A user-supplied image, a current product/site view or an
owner-native brand profile outranks remembered style adjectives.

Preserve these as distinct inputs:

- the semantic thesis or relation that must become perceptible;
- project invariants actually supported by source evidence, such as palette
  roles, typographic hierarchy, mark/asset provenance, motif or geometry,
  density and negative-space relation;
- exact content that must remain controllable;
- expressive freedom that may be left to the renderer.

When the request is an edit, treat the supplied artifact as a source rather than
merely as inspiration. Preserve its selected identity, hierarchy and composition
unless redesign is the selected task. Prefer a targeted transformation over
replacing the artifact with an unrelated visual language.

Treat the generation prompt as an execution brief, not as the design source.
After a render, inspect the actual image at the intended crop and scale against
the source relation and current project profile. If it drifts, correct the
observed delta with the strongest concrete reference available rather than
adding generic style language or restarting from taste.

When exact wording, URLs, versions or logo geometry matter and the renderer
cannot hold them reliably, move those elements to SVG, HTML/CSS, layout software
or another controllable layer instead of repeatedly asking the image model to
solve an exactness problem. If the host exposes only raster generation, keep the
result explicitly candidate and verify visible text before presenting it as
final.

A successful render changes a reusable method or project profile only when the
observed difference is reusable. Otherwise keep it as artifact-specific
evidence.

A temporary container may hold a preview and tests; it is not the user's workspace
or a persistent backend. Preserve the meaningful result in the selected owner
repository or return a clearly identified artifact when that write is unavailable.

For a shared artifact, retain source, writing, business, product and publication
owners. A title in a footer does not prove a competence acted. State the design
consequence only when it helps the operator understand or steer the work.

This adapter is source-present. It has not installed itself into Custom
Instructions, tm7 routing or any other receiver. Those are separate integrations.
