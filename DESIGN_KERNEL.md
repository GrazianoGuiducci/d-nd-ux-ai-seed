# D-ND Design Kernel

Version: **0.1.0** · Owner: **d-nd-ux-ai-seed** · Form: **compositional design-domain kernel**

This kernel forms perceptual, visual, spatial, temporal and interactive
expressions of a real object. A capable receiver exercises its methods with the
sources and tools actually available. The kernel is neither a new model nor a
renderer, a site runtime, a fixed style or a department that waits for finished
copy.

The existing **Agentic UX Seed** remains this repository's portable UX-behaviour
library. Its package, components, public adoption skills and release identity are
not replaced by the Design Kernel. The Design Kernel source lives in `design/`
and is not implicitly added to that npm distribution.

## Enter through the work

When the function and its source are already known, use the relevant competence
directly. On reentry, [CURRENT](design/state/CURRENT.md) identifies the live
resultant. [The manifest](DESIGN_KERNEL_MANIFEST.json) locates owner-native methods
and optional domain relations; it is a discovery aid, not a per-turn checklist.

A design need can arrive from an operator, product, research, writing, business,
launch or a consequence of use. Business is not the compulsory caller. A platform
or wave can make a need pertinent, but is not a software trigger until a real
runtime implements and is authorised to operate it.

The current relation is:

```text
source / object / intent / receiving situation
+ pertinent design knowledge and project profile
+ actual means and effect boundary
-> perceptual or interaction composition
-> artifact / implementation brief / unchanged form / useful open possibility
-> observation of the resulting expression
-> correction or reusable learning at its proper owner
```

These are coupled relations, not serial approval stages. A source may change the
question while form is emerging; a rendered result may disclose a relation the
initial brief could not express. Preserve the resulting determination rather
than reopening it to demonstrate optionality.

## What this domain owns

The continuing object is **how meaning, possibility and action become
perceptible and usable**: medium choice, art direction, hierarchy, visual syntax,
spatial and temporal explanation, interaction, responsive composition, accessible
alternatives and the learning arising from them.

The kernel does not take over the truth of the represented object, authored
language, business direction, channel timing or publication authority. A strong
image cannot establish a mechanism that has not been supplied by its source.

## Compose the smallest useful field

| Material relation in the work | Native method |
| --- | --- |
| What should become perceptible; medium, brand, visual hierarchy or art direction | [Perceptual Composition](design/skills/perceptual-composition/SKILL.md) |
| Several relations need to be understood together in space | [Source-Grounded Infographic](design/skills/source-grounded-infographic/SKILL.md) |
| A change, sequence or consequence needs to become visible in time | [Source-Grounded Storyboard](design/skills/source-grounded-storyboard/SKILL.md) |
| A person navigates, decides, acts, interrupts or recovers | [Interaction Quality](design/skills/interaction-quality/SKILL.md) |
| A complete existing UX unit must be ported or adapted | Existing [portable adoption](skills/agentic-ux-seed/SKILL.md) and [repository selection](skills/d-nd-ux-ai-seed/SKILL.md) skills |

This is an initial reachable field, not an exhaustive design ontology. One method
can act alone. Another can become pertinent because the first discovers a
missing relation. A new function may deepen an existing method, form a temporary
composition or justify a new continuing owner; a name alone does not decide.

Do not implement the table as keyword routing. For example, "video" in a request
can identify a distribution constraint while the actual needed work is a readable
thumbnail; "landing" does not by itself select a workspace component or WebGL.

## Form before allocating machinery

First preserve the source relation and recognise what the receiver can already
understand. Determine what the artifact must let them see, distinguish or do.
Then compose the needed medium and behaviour. A social visual may open a question;
a diagram may express a relation; a product card may support selection; an
interactive surface may let the person explore. None is obligatory for all tasks.

Keep information that must be exact in a controllable layer. A generated image
can carry texture, metaphor or composition; labels, URLs, versions, state and
controls belong in editable text/vector/DOM when exactness changes use. Image
generation may propose a better visual relation, but that relation is reread
against the source rather than accepted as new product truth.

An impressive expression is welcome when it helps the object appear. Clarity is
not a compulsory sober style. Conversely, animation or a complicated graph must
not hide the subject, imply nonexistent operation or demand explanation before
the person can orient.

## Keep the invariants inside design

Source, actual object, intent, perceptual form and consequence remain causally
joined. This is the domain incidence of the shared KA/FDLA/competence-learning
relation, not a copy of a private root kernel and not a new founding theory.

In practice, inspect what the form itself adds: a connecting arrow can invent
synchronisation, a hierarchy can invent command authority, a glow can imply live
activity, a new label can invent a product. Correct that introduced meaning in
the artifact and the design method that produced it.

A later consequence can deepen understanding without rewriting the earlier
occurrence or pretending it was understood then. Keep a candidate, an observed
behaviour, an operator decision and a generalised method distinct. An earlier
faithful interpretation does not have to remain current after a material change.

No first audience model, pattern, palette or output contract is the boundary of
future possibility. Once a concrete design is selected, however, support and
exercise it; do not perpetually expand the menu.

## Compose with other owners

**Business / Launch** supplies the relationship, purpose, audience context,
carrier/wave and available continuation when those relations are part of the
work. It does not prescribe aesthetics on behalf of this domain.

**Editoriali or the receiving writing owner** participates as consequential
wording is conceived: copy, argument, narration, labels and captions. Writing
can change the visual proposal; visual constraints can make a wording revision
necessary. Do not supply a second copywriting system in this repository.

**UX-AI Kernel Design or the receiving explanation owner** contributes when the
person needs to understand the system's current movement in order to steer,
correct, stop or learn. That dialogic function is not art direction.

**Product / site / research owners** retain capability truth, technical state,
scientific claims and destination-specific contracts. **Publication owners**
retain exact send/deploy/publication effects. A multi-surface package owner
reconciles complementary artifacts; this kernel does not create another campaign
manager.

Use [EXCHANGE](design/EXCHANGE.md) only when a handoff needs an explicit contract.
The ordinary shared conversation may already supply it. An external owner that
is inaccessible is reported as such; a private source path is not treated as
usable capability in a public derivative.

## Form capability and return learning

Meta_Skill's formation relation and RepoKernel's source-preserving synthesis and
transfer informed this kernel. They are not required installed services. The
portable method is present here: understand the capability and its reasons,
reuse or compose existing knowledge, form only the useful continuing difference,
give it a usable entry, exercise it, and return the causal learning. A compiler,
scaffold or `SKILL.md` formatter is selected only when that mechanism serves the
actual output; none is the semantic generator by itself.

When a result teaches something reusable, change the closest method in this
same selected movement. Keep project palette/copy/state in the project profile;
interaction behaviour in Interaction Quality; spatial/temporal semantics in
their methods; missing activation in the entry. Cross-owner changes are returned
to that owner rather than silently applied. Unchanged knowledge is a valid result.

A passing structural test proves only the checked structure. A rendered fixture
proves only its observed behaviour. Later non-identical use is needed to claim
assimilation; first-encounter comprehension requires an actual receiver rather
than the author's self-endorsement.

## Present implementation boundary

This is a source-level kernel with controlled exercises, not an autonomous
orchestration service. [Receiver adapters](design/adapters/CHATGPT.md) describe
actual incarnation. Core 0.1.0, the old adaptive-surface PR, each design artifact
and the Agentic UX Seed release keep separate identities and evidence.
